## C. Actual synchronization incident and recovery

Initial live state: 3 lost reports, 2 found reports, one unfinished outbox event: **#72, lost_item_details, document #16**, attempts **0**, no recorded error. The payload had the expected tags/media/keywords/attributes fields. Atlas server selection failed; all three cluster members reported TLS handshake rejection with `ERR_SSL_TLSV1_ALERT_INTERNAL_ERROR`. The cluster-side reason for that rejection could not be proven from the driver alone. Credentials and full connection strings were never printed.

After the user checked Atlas connectivity and replied ready, full setup connected successfully and installed the new index non-destructively. `npm run db:sync` returned **processed: 1, pending: 0, failed: 0**. Event #72 remains in SQL with processed_at set. Existing SQL domain counts remained 3 lost / 2 found; integrity checks found zero orphaned report/match/claim references, duplicate pairs or duplicate approved ownership outcomes. See [live storage evidence](testing/results/audit-live-storage.json).

MySQL is authoritative for identities, relationships, state transitions and durable queued events. MongoDB is the indexed document read model. This is eventual consistency, not one atomic cross-database transaction. Matching uses the latest relevant committed recovery snapshot when necessary. During an outage, a legacy report without such a snapshot still requires MongoDB; unavailable data is not silently treated as empty.

Writes remain unfinished until Mongo acknowledges them. Per-document ordering prevents an earlier retry overwriting a later update. A named SQL lock prevents simultaneous unsafe workers. Retry delays start at 5 seconds, double, and cap at 1 hour; eight failures exhaust automatic attempts. Validation/authorization errors require manual attention. Admin's explicit retry preserves payloads and attempt history. No database was reset, no collection was cleared, and no pending record was discarded to hide the incident.

## E. Exact Windows setup and run commands

From the project root, preserve an existing configured .env.local. For a new installation only, copy .env.example and fill MySQL/Mongo/Google settings locally. Never put secrets in Git or chat.

```powershell
npm ci
# Existing installation: safe repeatable migrations, no reseed required.
npm run db:setup
npm run typecheck
npm test
npm run build
npm start
```

In a second terminal:

```powershell
npm run db:worker
```

First-time local demo provisioning (after configuring distinct demo emails):

```powershell
node scripts/init-local-env.mjs --demo
npm run db:setup
npm run seed
npm run seed:demo
npm run dev
```

The initializer preserves configured database credentials and creates the local session secret. The demo uses explicit seeded role accounts, not published passwords. Disable DEMO_LOGIN_ENABLED for non-local deployment. Real Google registration always starts as Student; an Admin assigns Staff access.

`db:setup` applies outbox-reliability.sql without deleting records, refreshes procedures, and installs the optional unique audit event index. It is repeatable, including an interrupted run of this new upgrade. MySQL DDL implicitly commits; maintain normal backups. If MongoDB is unavailable, `npm run db:setup -- --sql-only` can finish SQL upgrades; rerun full setup after recovery.

For isolated tests, start local mongod on 27018 (PowerShell example in [README](../README.md)), leave ports 3100/3101 free, then run:

```powershell
npm run test:audit
```

Set AUDIT_MONGODB_URI only to an explicitly selected test server. Tests create separate database names automatically and retain fixtures. The older `test:integration` command cleans its own fixtures by default, so use test:audit for the retained-data audit workflow.

## F. Troubleshooting and limits

- Pending/transient write: run db:worker or inspect Admin → Sync; respect the displayed next attempt. A completed write removes its warning.
- Permanent/exhausted write: inspect its classified failure, correct the underlying data/configuration, then request an Admin retry. Payloads and attempts remain intact.
- Atlas TLS/server selection failure: check cluster availability, network access, DNS and local network/TLS policy. Do not disable TLS certificate validation or empty the queue.
- Worker busy: another worker owns the SQL lock; refresh health shortly. Completed records are not reprocessed.
- Missing legacy recovery snapshot during outage: restore Mongo connectivity; the system does not invent document values.
- Rejected claim: the existing one-claim-per-person/item rule remains; matched reports stay matched for desk follow-up. Reopening/overriding terminal ownership decisions is intentionally unsupported.

No confirmed failing automated checks remain in this run. Human Google authorization and university presentation/contribution formalities remain external actions; no personal authorship or provider success is fabricated.
